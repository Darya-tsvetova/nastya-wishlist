ВИШЛИСТ НАСТИ, ИТОГОВАЯ РЕДАКЦИЯ 3.0
============================================

СОДЕРЖИМОЕ
index.html — полный HTML/CSS/JavaScript в одном файле.
setup.sql — схема базы, ограничения, права доступа и атомарное бронирование.

КАК ВЫГЛЯДИТ ПОВЕДЕНИЕ
1. Настя входит по письму, создаёт подарки, вставляет HTTPS-ссылку на товар, по желанию цену, описание и HTTPS-ссылку на картинку, выбирает приоритет.
2. Гости открывают одну ссылку на сайт. Создаётся анонимная сессия Supabase, без ввода имени гостя.
3. Гость нажимает «Забронировать и перейти», подтверждает выбор. Приложение открывает временную вкладку и отправляет запрос в БД.
4. При успешном ответе сервера новая вкладка открывает товар; статус подарка становится «Уже забронировано» для всех. При ошибке временная вкладка закрывается. Если браузер заблокировал вкладку, появляется ссылка на магазин после успешного бронирования.
5. Имя гостя не запрашивается и не показывается. Supabase всё равно технически создаёт ID анонимной сессии и обрабатывает запросы; обещать абсолютную анонимность некорректно.
6. Сайт получает уведомления Supabase Realtime и дополнительно обновляется каждые 15 секунд и при возврате на вкладку. Дубли брони предотвращает SQL UPDATE, а не только интерфейс.

УСТАНОВКА
1. Создайте проект https://supabase.com и сохраните HTTPS Project URL и PUBLISHABLE key.
2. В Authentication > Providers разрешите Anonymous Sign-Ins и Email OTP. Настройте доставку почты и шаблон писем. В Authentication > Users предварительно создайте/пригласите учётную запись Насти с её действительным email. Это важно: в коде стоит shouldCreateUser:false, вход не регистрирует незнакомые адреса автоматически.
3. В файле setup.sql замените все ТРИ NASTYA_EMAIL_HERE на email Насти (строго такой же, как в Auth); выполните SQL в SQL Editor нового проекта. Внимание: НЕ выполняйте SQL поверх старой БД без проверки миграции и сохранности записей.
4. В index.html внесите значения SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, OWNER_EMAIL. Используйте только publishable/anon ключ. Никогда не используйте secret/service_role в HTML!
5. Опубликуйте index.html на HTTPS-хостинге статических файлов (например, https://app.netlify.com/drop). В Supabase Authentication > URL Configuration добавьте полный URL опубликованной страницы в Redirect URLs и Site URL.
6. Отправьте Насте ссылку, попросите войти по почте и заполнить подарки. Гостям отправьте ЭТУ ЖЕ ссылку после наполнения.

ВЫВОД НА РЕАЛЬНУЮ ПУБЛИКАЦИЮ
Перед отправкой гостям протестируйте:
- вход Насти с действительным письмом;
- добавление, изменение, удаление подарков;
- бронирование с двух независимых браузеров одновременно;
- переход в магазин только при успешной брони;
- блокировку повторного бронирования;
- анонимность: статус всем виден, имена нигде не запрашиваются;
- телефон iOS/Android и браузерную блокировку всплывающих окон.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- Бронирующий не покупает товар автоматически: только резервирует намерение подарить.
- Любой человек, знающий ссылку, способен сделать много бронирований; для публичного массового использования добавьте серверные лимиты запросов, CAPTCHA либо гостевые коды.
- Снять бронь можно через Supabase Dashboard: Table Editor > gifts > reserved=false. Публичной кнопки отмены нет, поскольку брони анонимны.
- Данные в базе настоящие, но до настройки и публикации приложение не является работающим онлайн-сервисом.
- Магазины могут запретить загрузку изображений по прямой ссылке: в таком случае показывается 🎁.
- Поскольку пользовательские ссылки ведут во внешние магазины, Насте стоит проверять адрес магазина перед публикацией подарка.
- Код использует внешний CDN Supabase JS и Google Fonts; загрузка зависит от доступности этих ресурсов.
- Не обещайте абсолютной приватности: Supabase Auth и хостинг сохраняют технические логи.

ПРИМЕЧАНИЕ О ПРАВАХ
RLS разрешает добавление/изменение/удаление только подтверждённой учётной записи Насти.
Серверная функция reserve_gift вызывается гостем с анонимной авторизацией.
Поле reserved запрещено менять клиенту напрямую посредством прав SQL на столбец.
Результат функции true означает, что данному вызову удалось занять свободный подарок; false означает, что он уже занят или недоступен.

ПРОВЕРКА ФИНАЛЬНОЙ ВЕРСИИ
- Проверьте работу проекта с реальным Supabase и двумя браузерами до распространения ссылки.
- Попапы могут блокироваться: приложение показывает запасную ссылку на товар после успешной брони.
- Анонимные входы Supabase имеют ограничения и могут требовать CAPTCHA при массовой нагрузке.
- Если гость забронирует подарок ошибочно, организатор сбрасывает reserved в Supabase Table Editor.
